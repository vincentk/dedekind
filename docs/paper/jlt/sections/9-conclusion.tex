\subsection{Conclusion}
\label{sec:conclusion}

Three rules on standard \Cpp{23} delimit a part of the language, Jlt, in which every definition has a meaning in System~F.
For the kernel, the translation is defined and proved on paper to preserve types and values, and termination and parametricity follow from its target under stated assumptions (Section~\ref{sec:translation}).
For the sugar around the kernel, the reading is argued and tested, not proved.
That \Cpp{} evaluates a kernel program as the calculus does is assumed, with constant evaluation as the reference.

The compiler holds no rule in full; the rest is held by the author, a linter and a reviewer (Table~\ref{tab:posture}, Section~\ref{sec:limits}).
The linter says of each definition whether it is shown to be in Jlt, and what it cannot settle it names.
Four things follow as work not done here: rows for the forms it leaves undecided, sums among them; a test beside its kernel reading for every derived form; the library that motivated Jlt brought fully under its own linter; and a mechanisation of the proofs, as Siek and Lumsdaine did for $F^G$ in Isabelle~\cite{siek2004formalization}.
A pattern lies beyond them: what is known when a program is built is computed then, in part or in whole, and what crosses to run time is state whose size is fixed at compile time.
So the computations that specialise well may be those that run in small state over an unbounded input, one element at a time, by a step that is a function of Jlt: the streaming algorithms~\cite{alon1999space}.

Nothing was added to the language, the compiler or the library: what was added is a boundary, meant as a route rather than a wall, which a team takes one file and one rule at a time.
Dos Reis and Stroustrup remarked in 2006 that a type class and its instances ``correspond closely to \Cpp{}'s notion of template partial or full specialization'', which ``morally is what happens when the dictionaries, in the dictionary passing style translation [\ldots], are optimized away''~\cite[Section~6.2]{dosreis2006specifying}.
That is a statement about the general case.
This paper gives up the general case for a fragment of the language as shipped, and in return replaces ``morally'' by ``mechanically'': membership in the fragment is checked in continuous integration.
