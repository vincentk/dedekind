\section{Featherweight Jlt}
\label{app:fjlt}
% Design (decided on #981): no overlapping instances; fold and explicit fuel as
% the only recursion; laws as ordinary values; multi-parameter instances with
% contexts; associated types and same-type constraints as in F^G; instance
% resolution terminates because contexts mention only proper subterms;
% struct templates are type operators (abbreviations); dictionaries are

\subsection{Syntax}
\label{app:fjlt:syntax}

FJlt is a subset of \Cpp{23}.
Figure~\ref{fig:fjlt-syntax} gives its grammar in the style of Featherweight Java: $\overline{\alpha}$ abbreviates a sequence $\alpha_1, \ldots, \alpha_n$, a construct written over a sequence is repeated for each element, and the separators the host language wants (commas, \cppinline{&&}, semicolons) are implied.
Every FJlt program is a \Cpp{23} program with the same meaning; the converse fails by design.
The listings of Section~\ref{sec:translation} are FJlt programs, with \cppinline{static_assert(e)} read as the claim that the closed term $e$ evaluates to \cppinline{true}.

Metavariables: $\alpha, \beta$ range over type variables, $b$ over base types (\cppinline{bool}, \cppinline{std::uint64_t}), $O$ over the standard function-object types (\cppinline{std::plus<>}, \cppinline{std::logical_and<>}, \ldots), $C$ over concept names, $t$ over trait names, $f$ over function names, $x$ over term variables and $c$ over constants.

\[

P &::=& \overline{D}\; e & \text{program} \\[3pt]
D &::=& \texttt{template <typename }\overline{\alpha}\texttt{> concept } C \texttt{ = } \overline{R}\texttt{;} & \text{shape} \\
  & | & \texttt{template <> inline constexpr } \tau\; t\texttt{<}\overline{\tau}\texttt{> = } e\texttt{;} & \text{instance} \\
  & | & \texttt{template <typename }\overline{\alpha}\texttt{> requires } \overline{Q}\texttt{ inline constexpr } \tau\; t\texttt{<}\overline{\tau}\texttt{> = } e\texttt{;} & \text{instance with context} \\
  & | & \texttt{template <typename }\overline{\alpha}\texttt{> requires } \overline{Q}\texttt{ constexpr } \tau\; f\texttt{(}\overline{\tau\; x}\texttt{) \{ return } e\texttt{; \}} & \text{generic function} \\[3pt]
R &::=& Q & \text{nested shape} \\
  & | & t\texttt{<}\overline{\tau}\texttt{>} & \text{declared judgment} \\
  & | & \texttt{requires (}\overline{\texttt{const }\tau\; x}\texttt{) \{ } \overline{\texttt{\{ }e\texttt{ \} -> std::same\_as<}\tau\texttt{>;}} \texttt{ \}} & \text{operations} \\[3pt]
Q &::=& C\texttt{<}\overline{\tau}\texttt{>} & \text{constraint} \\[3pt]
\tau &::=& \alpha \;\mid\; b \;\mid\; O \;\mid\; \texttt{std::pair<}\tau\texttt{, }\tau\texttt{>} & \text{type} \\[3pt]
e &::=& x \;\mid\; c \;\mid\; f\texttt{<}\overline{\tau}\texttt{>(}\overline{e}\texttt{)} \;\mid\; O\texttt{\{\}(}\overline{e}\texttt{)} \;\mid\; t\texttt{<}\overline{\tau}\texttt{>} & \text{term} \\
  & \mid & \texttt{std::pair\{}e\texttt{, }e\texttt{\}} \;\mid\; e\texttt{.first} \;\mid\; e\texttt{.second} & \\
\end{array}
\]
\normalsize
\caption{The syntax of FJlt, a subset of \Cpp{23}.
A program is a sequence of declarations and a closed term.
A shape is a concept; its requirements are nested shapes, declared judgments (traits of type \cppinline{bool}) and operations with their result types.
An instance is an explicit specialisation of a variable template, an instance with a context a constrained partial specialisation.
A generic function is a \cppinline{constexpr} function template with a \cppinline{requires} clause and a single \cppinline{return}.
Terms are variables, constants, calls with explicit type arguments, applications of a function object, trait lookups and pairs.}
\label{fig:fjlt-syntax}
\end{figure}
