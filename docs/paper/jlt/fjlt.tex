\section{Featherweight Jlt}
\label{app:fjlt}
% Design (decided on #981): no overlapping instances; fold and an explicit budget as
% the only recursion; laws as ordinary values; multi-parameter instances with
% contexts; associated types and same-type constraints as in F^G; instance
% resolution terminates because contexts mention only proper subterms;
% struct templates are type operators (abbreviations); dictionaries are

\subsection{Syntax}
\label{app:fjlt:syntax}

FJlt is a subset of \Cpp{23}, parametric in a \emph{signature} $\Sigma$ of carriers.
A carrier is in $\Sigma$ on three conditions: it is \cppinline{std::semiregular}; the operations a program uses on it are \cppinline{constexpr} and total; and it has an image in the target, a constant type with those operations as constants, and an iterator if it is inductive.
The compiler decides semiregularity and that an operation is \cppinline{constexpr}; totality is a reading, since neither a \cppinline{constexpr} declaration nor a successful evaluation shows an operation defined on every input, and it is what Lemma~\ref{lem:progress} needs and what keeps \cppinline{int}'s overflow and division out; the image is a definition.
A type enters $\Sigma$ by meeting the conditions, not by being named here, which is the structural admission the fragment is named for; the carriers this paper's listings use are \cppinline{bool}, \cppinline{size_t}, \cppinline{std::string}, with concatenation and the comparisons as its operations, allocation failure aside, and the finite enumerations a program or the library declares, such as \cppinline{Ternary} and \cppinline{ArrowLaw}, each a finite sum of units with equality.
Figure~\ref{fig:fjlt-syntax} gives the grammar in the style of Featherweight Java: $\overline{\alpha}$ abbreviates a sequence $\alpha_1, \ldots, \alpha_n$, a construct written over a sequence is repeated for each element, and the separators the host language wants (commas, \cppinline{&&}, semicolons) are implied.
The overbar is also how a parameter pack reads: a variadic declaration is the family of its arities, each a declaration of the grammar, and a fold expression at arity $n$ is the nested term; what the overbar does not give is a statement about all arities at once.
Every FJlt program is a Jlt program, a \Cpp{23} program that keeps the three rules, with the same meaning. The converse, for a Jlt program written in this grammar, is the adequacy argument of Section~\ref{sec:translation:adequacy}.
The listings of Section~\ref{sec:translation} are FJlt programs, with \cppinline{static_assert(e)} read as the claim that the closed term $e$ evaluates to \cppinline{true}.

Metavariables: $\alpha, \beta$ range over type variables, $b$ over the carriers of $\Sigma$, $O$ over the function-object types, the standard templates (\cppinline{std::plus}, \cppinline{std::logical_and}, \ldots) and the operations a program declares, $r$ over ranges, $\oplus$ over the operations of $\Sigma$, total by the second condition: on unsigned carriers addition, subtraction, multiplication and the bitwise operations, which wrap, and the comparisons; on \cppinline{bool} the logical operations; division and remainder are partial and not admitted, and the standard function objects $O$ are those of the same operations, $C$ over concept names, the standard ones included (\cppinline{std::semiregular} is the shape Rule~1 requires of every carrier), $S$ over the two standard result-type concepts \cppinline{std::same_as} and \cppinline{std::convertible_to}, $f$ over function names, $x$ over term variables and $c$ over constants.

\paragraph{Reading the grammar.}
A program is a sequence of declarations and a closed term.
A shape is a concept; its requirements are nested shapes, laws (closed \cppinline{bool} terms) and operations with their result types, exact (\cppinline{std::same_as}) or up to conversion (\cppinline{std::convertible_to}).
A constraint may be negated, \cppinline{!C<T>}, as a \cppinline{requires} clause can write it; a negation carries no evidence, and at concrete types it holds where $C$ does not (\textsc{E-Not}).
A trait is a function template declared and deleted, indexed by a carrier and a value of the operation; an instance is an explicit specialisation of it at a carrier; an instance with a context is a generic function whose \cppinline{requires} clause is the context.
A generic function is a \cppinline{constexpr} function template with a \cppinline{requires} clause and a single \cppinline{return}; \cppinline{auto} in a listing names the type the body has, and a parameter written \cppinline{const τ} or \cppinline{const τ&} is the parameter $\tau\; x$ of the grammar, since a value is immutable and a reference to one denotes it.
The standard function objects and the operations a program declares (a struct with fields and a call operator, itself generic where the listing writes \cppinline{auto}; a former such as \cppinline{Compose} is one) are the only function objects; a term applies one by constructing it, with its fields, and reads a field with \cppinline{.}; the call operator is \cppinline{const}, so applying a function object observes it, as Rule~1 requires of a value.
Terms are variables, constants, function names, calls with explicit or deduced type arguments, applications, arithmetic and comparisons, conditionals, pairs, sums and boxed values.
A sum is a type of a family $\mathcal{S}$ that, like $\mathcal{R}$ below, is defined by conditions: two injections $\iota_1, \iota_2$ and a total case form, \texttt{case(}$s$\texttt{, }$f$\texttt{, }$g$\texttt{)} applying $f$ or $g$ to the injected value, each instance spelling them in \Cpp{}.
\cppinline{optional<τ>} is $1 + \tau$, with $\iota_1$ = \cppinline{nullopt}, $\iota_2\,e$ = \cppinline{optional\{e\}} and the case \cppinline{s.transform(g).value_or(f)}, $f$ the value for the empty one; \cppinline{variant<τ₁, τ₂>} is $\tau_1 + \tau_2$, with $\iota_i\,e$ = \cppinline{variant<τ₁, τ₂>(in_place_index<i-1>, e)}, both alternatives spelled, and the case dispatched on the index, \cppinline{s.index() == 0 ? f(get<0>(s)) : g(get<1>(s))}, each \cppinline{get} guarded by the test, as the library's \cppinline{Copairing} writes it; \cppinline{std::visit} is the special case in which one operation, its call operator entailed at both summands, serves as both branches.
\cppinline{*} on an optional and \cppinline{std::get} on a variant are partial and are not terms; under a guard they are the case form.
A box is built and read, and nothing else: there is no term for \cppinline{get}, \cppinline{use_count} or \cppinline{==} between boxes, so no program can ask which box holds a value, and that absence is what makes a box a value.
There are two recursion primitives, one per kind of finiteness.
\cppinline{fold_left} folds over a range of fixed length, a value $r$ of a family $\mathcal{R}$ that, like $\Sigma$, is defined by conditions and not by a list: $r$ has a length $|r| \in \mathbb{N}$, fixed before the fold starts, and, when $|r| > 0$, a head and a tail $\mathit{next}\,r$ with $|\mathit{next}\,r| = |r| - 1$; \textsc{S-Fold} consults $|r|$ before it asks for either, and in the target both are extended to the empty range by an arbitrary value, which the iterator never reaches, since it runs $|r|$ times.
Each instance $R$ of $\mathcal{R}$ over an element type $\tau$ contributes to the target a state type $\llbracket R \rrbracket$, a constructor constant $c_R$ applied to the translations of its arguments, and its operations as constants, $|\cdot| : \llbracket R \rrbracket \to \mathbb{N}$, $\mathit{head} : \llbracket R \rrbracket \to \llbracket \tau \rrbracket$ and $\mathit{next} : \llbracket R \rrbracket \to \llbracket R \rrbracket$; the state of \cppinline{chain(n, out)} is $\llbracket N \rrbracket$, the count, that of \cppinline{transform(r, g)} is $\llbracket R \rrbracket$, that of \cppinline{repeat(x, n)} is $\llbracket \tau \rrbracket \times \mathbb{N}$, that of \cppinline{iota(i, j)} is $\mathbb{N} \times \mathbb{N}$, and that of \cppinline{chain_view{lo, hi}} is $\llbracket C \rrbracket \times \llbracket C \rrbracket$ for the chain $C$.
The listings' ranges are \cppinline{chain(n, out)}, the chain of a count under its destructor, with head $n$ and tail \cppinline{chain(out(n), out)}, empty where \cppinline{out(n)} is nothing, its length the number of steps to that delimiter, finite because the step descends (Section~\ref{sec:posture}, Figure~\ref{fig:structures}); \cppinline{transform(r, g)}, the image of a range under an arrow, with head \cppinline{g(head r)}, tail \cppinline{transform(next r, g)} and length $|r|$; \cppinline{repeat(x, n)}, $n$ copies of $x$, with head $x$ and tail \cppinline{repeat(x, n - 1)}; \cppinline{iota(i, j)} with $i \le j$, the naturals from $i$ below $j$, with head $i$ and tail \cppinline{iota(i + 1, j)}, the condition $i \le j$ being the standard view's, whose reversed endpoints are undefined behaviour rather than an empty range; and \cppinline{chain_view{lo, hi}}, the elements of a finite chain from \cppinline{lo} to \cppinline{hi} walked by the covering step, with head \cppinline{lo}, tail the interval from the cover of \cppinline{lo}, and empty when \cppinline{lo > hi}, of which \cppinline{iota} is the instance on \cppinline{size_t}.
\cppinline{cata(alg, t)} folds over a term: an operation whose fields are terms is a node, a term is a finite composition of nodes, and the fold applies the algebra to each node and the folded values of its legs, one node at a time.
The type formers are productions, not members of $\Sigma$, because the translation acts on them structurally: pairs as products, optionals as sums, boxes as unary products; a former enters when it has such an image, as \cppinline{std::variant} does as a sum, above, and \cppinline{std::vector} would as lists with their fold, which is absent because no listing needs it.

\subsection{Typing}
\label{app:fjlt:typing}

Three judgments, in the usual shape.
$\Delta \Vdash Q$ says that the constraint $Q$ is \emph{entailed} in the context $\Delta$, which holds type variables and assumed constraints.
$\Delta; \Gamma \vdash e : \tau$ types a term.
$\vdash D$ says a declaration is well formed, and a program is well formed when its declarations are and its closed term has a type.
Figure~\ref{fig:fjlt-typing} gives the rules that carry weight; the ones for constants, pairs, boxes, conditionals and the arithmetic of base types are the obvious ones and are omitted.

\paragraph{Resolution.}
A trait call $f\texttt{<}\overline{\tau}\texttt{>}$ at concrete types \emph{resolves} to a declaration of $f$ in two steps, as \Cpp{} resolves an overloaded template: first the most specific of the generic functions whose head matches $\overline{\tau}$ and whose context is entailed, the deleted primary among them, then, if that is the primary, its explicit specialisation at $\overline{\tau}$ if there is one.
The deleted primary never resolves, which is how an operation nobody registered fails a shape.
Well-formedness requires resolution to be a function, in two cases.
At concrete types, no two specialisations share a head, and among the generic functions whose head matches and whose context is entailed there is a unique most specific one, by head and then by context, as \Cpp{} orders constrained templates; \Cpp{} rejects the program where there is none.
At a type variable, in a body with context $\Delta$, a call resolves only when its choice survives every instantiation of the body: every candidate whose head unifies with the call's types and that would be more specific than the chosen one is excluded by a constraint $\Delta$ decides, entailing it or its negation.
That is GHC's rule for overlapping instances~\cite{ghc2024overlapping}, which refuses to commit to an instance the types do not yet decide; \Cpp{} does not hold it, and a call it would refuse is a body that varies with a type through a constraint it did not declare, a breach of Rule~2, which the repository's tool reports where it can see one (Section~\ref{sec:limits}).
Well-formedness also requires every context to mention only proper parts of the head's type arguments, so that resolution terminates~\cite{sulzmann2007understanding}.
It also orders the declarations: the body of an instance, a generic function or an operation may call only declarations that precede it, and a trait call in a body may resolve only to a declaration that precedes the body, with one exception: a generic function may call itself at type arguments that are proper subterms of its own, so that its instantiations are ordered by the size of their type arguments and no instantiation calls itself.
So no instantiation calls itself, directly or through others, the translation needs no recursive binding, and the only recursion in a program is that of the two folds.
The exception is what admits the library's \cppinline{cata} over typed terms, whose recursion is on the type of the term and not on a value.

\paragraph{Reading the rules.}
\textsc{E-Law} is where a law is a value: entailment evaluates it, so a shape with a law is satisfied only at instances whose certificate holds, and the stratification of laws (closed terms of base type) keeps typing and evaluation from chasing each other.
Its premise is closed because evaluation is defined on closed terms only: a law is evaluated where a record is built, at concrete types, and at a type variable a law is entailed only through an assumed shape that lists it, by \textsc{E-Law-Assumed}, as an operation is through \textsc{T-Req-Assumed}.
The side condition of \textsc{E-Shape} makes entailment syntax-directed: an assumed shape is its record variable and is never rebuilt field by field, which is what Theorem~\ref{thm:coherence} needs.
\textsc{E-Op} reads $S$ as equality for \cppinline{std::same_as} and as conversion for \cppinline{std::convertible_to}; in the second case \textsc{T-Req-Assumed} lets a body use the result only at the declared $\tau$, so the conversion the dictionary makes once, in the field, is the conversion the source would make at every use, and a body that used the unconverted result, say to compare two of them at their own type, would be using an operation the constraint did not name, which the typing refuses and \Cpp{} accepts: the one place FJlt is stricter than the compiler.
The library needs the conversion form about as often as the exact one (161 requirements against 181), where a requirement's expression is an lvalue of the wanted type (\cppinline{const T&} is not \cppinline{same_as<T>}; \cppinline{IsPointed}'s unit), where a step returns a proxy for the carrier (\cppinline{HasNNOStep}'s successor), or where an object is presented by another type (\cppinline{Presents}); in each, the body uses the result at the declared type, which is the discipline just stated.
The requirements of a shape, in \textsc{T-Req-Assumed} and \textsc{E-Law-Assumed}, are its own and, transitively, those of its nested shapes, so that an assumed \cppinline{IsCommutativeMonoid<T, Op>} yields the operations and the associativity law of \cppinline{IsMonoid<T, Op>}; the dictionary projects along the path of nested fields, $q_C.m.r$ for a requirement $r$ of the nested shape held in field $m$.
When more than one assumed requirement matches an operation, the rules take the leftmost shape of the \cppinline{requires} clause and, within it, the first matching requirement in declaration order, so both rules are functions of the body; once instantiated the candidates denote one operation, by Lemma~\ref{lem:resolve}, and the choice fixes which is projected before that.
\textsc{T-Req-Assumed} is the rule that makes \textsc{D-Generic} a definition check: inside a constrained body, an operation on a constrained type is typed only as an instance of a requirement of a constraint in $\Delta$, \cppinline{Op{}(x, x)} as the pattern \cppinline{{ Op{}(a, b) }} at $a, b := x$, and \cppinline{unit<T>(Op{})} as the parameterless pattern \cppinline{{ unit<T>(Op{}) }}; a trait is reachable the same way.
The range rule types a range of $\mathcal{R}$ by its instance's conditions, \cppinline{iota(i, j)} only at $i \le j$, and \textsc{S-Fold} preserves them, since $\mathit{next}$ does.
In \textsc{T-Cata}, $\mu F$ is a term type, the inductive type of the nodes that build it, and the algebra is applied to each node together with the folded values of its legs, the node itself still in hand, which is the library's interface (\cppinline{alg(t, cata(alg, leg)...)}) and the paramorphism's.

\subsection{Evaluation}
\label{app:fjlt:evaluation}

Evaluation is small-step and call-by-value on closed terms, $e \longrightarrow e'$, with values and evaluation contexts
\[
\begin{array}{rcl}
v &::=& c \mid f \mid O\texttt{<}\overline{\tau}\texttt{>\{}\overline{v}\texttt{\}} \mid \texttt{std::pair\{}v\texttt{, }v\texttt{\}} \mid \iota_1\,v \mid \iota_2\,v \mid \texttt{std::optional\{}v\texttt{\}} \mid \texttt{std::nullopt} \\
  &\mid& \texttt{std::make\_shared<const }\tau\texttt{>(}v\texttt{)} \\
E &::=& [\,] \mid f\texttt{<}\overline{\sigma}\texttt{>(}\overline{v}\texttt{, }E\texttt{, }\overline{e}\texttt{)} \mid E\texttt{(}\overline{e}\texttt{)} \mid v\texttt{(}\overline{v}\texttt{, }E\texttt{, }\overline{e}\texttt{)} \mid E \oplus e \mid v \oplus E \mid E \texttt{ ? } e \texttt{ : } e \\
  &\mid& \iota_i\,E \mid \texttt{case(}E\texttt{, }e\texttt{, }e\texttt{)} \mid \ldots
\end{array}
\]
where the elided contexts are the remaining argument positions of pairs, optionals, boxes, projections, constructions and folds, each evaluated left to right.

The context grammar picks one redex per non-value term, so the relation is deterministic.

\subsection{Translation into System F}
\label{app:fjlt:translation}

The target is System~F with products, sums, the carriers of $\Sigma$ taken as constants with their total operations, and inductive types with their iterators: the natural numbers with $\mathit{iter} : \forall\sigma.\,\mathbb{N} \to (\sigma \to \sigma) \to \sigma \to \sigma$, reducing by $\mathit{iter}\,(k{+}1)\,s\,z \longrightarrow \mathit{iter}\,k\,s\,(s\,z)$ and $\mathit{iter}\,0\,s\,z \longrightarrow z$, and for each term type $\mu F$ its iterator $\mathit{fold}_F : \forall\sigma.\,(F(\sigma) \to \sigma) \to \mu F \to \sigma$, reducing one constructor at a time, $\mathit{fold}_F\,\beta\,(\mathrm{in}\,n) \longrightarrow \beta\,(F(\mathit{fold}_F\,\beta)\,n)$; the paramorphism, which also hands each node itself to the algebra, is the iterator at $\mu F \times \sigma$ with the node rebuilt beside the result, as usual.
Reduction in the target is full $\beta$-reduction, any redex anywhere, together with the unfolding of a defined name $f_{\overline{\tau}}$ to its body and the two iterator rules; no evaluation order is imposed, which is the setting of the normalisation and confluence results used below.
Records are nested pairs; the extension by inductive types with their iterators is strongly normalising and confluent~\cite{girard1989proofs,bohm1985automatic}, so the target is conservative over System~F for everything this appendix uses, and the one-constructor-at-a-time iterators are what make Theorem~\ref{thm:simulation} exact where a Church encoding, unfolding all at once, would not be.
Figure~\ref{fig:fjlt-translation} gives the translation.

\paragraph{Reading the translation.}
A function object is a pair of its fields and its call function, so a fieldless \cppinline{std::plus<size_t>} is $((), \mathit{plus})$, passing it as a step uses its second component, and reading a field uses its first.
A trait has no image of its own; its specialisations are closed terms $f_{\overline{\tau}}$, and a generic function that serves as an instance with a context is the function from records to a record that \textsc{E-Shape} builds its dictionary with.
Where \cppinline{size_t} is read as $\mathbb{N}$, $\llbracket n \rrbracket$ is the natural number that is $n$'s value; the translation of a term with a runtime \cppinline{n} is the term with $n$ as a free variable of type $\mathbb{N}$, and Theorem~\ref{thm:simulation} is stated for closed terms.
The call function of a constrained operation abstracts over its dictionaries as a generic function does, and an application supplies them.
The iterator is the catamorphism of the chain of a natural number, a fold over any range of $\mathcal{R}$ is that catamorphism at the range's length with the range's position carried beside the state, and \cppinline{cata} is the catamorphism of a term's inductive type; a term type translates to $\mu F$ with a node translating to its constructor applied to its fields.
The library's set recursion is the first two, and its one engine over terms is the third.
A box translates to a unary product rather than to nothing, on purpose: a box's only observable is its content, so which box holds it is erased, and the unit component keeps unboxing a step on both sides, which Lemma~\ref{lem:forward} needs.
Its one non-local ingredient is the \emph{dictionary} of an entailment: $\llbracket \Delta \Vdash Q \rrbracket$ is the record that witnesses $Q$, built by the same recursion as resolution.

\subsection{Theorems}
\label{app:fjlt:theorems}
% Proof sketches for the statements of Section~\ref{sec:guarantees}.  They
% rest on the typing rules (A.2), the evaluation rules (A.3) and the
% translation (A.4), which are still to be written; each sketch names the
% cases it needs from them.  Full proofs and a mechanisation are future work.

The statements are in Section~\ref{sec:guarantees}; the proofs are here, complete relative to the rules of Figures~\ref{fig:fjlt-typing} to~\ref{fig:fjlt-translation}, whose omitted cases (constants, pairs, optionals, conditionals, the arithmetic of base types) are the textbook ones.
Throughout, $\Sigma$ is any signature meeting the three conditions of Section~\ref{app:fjlt:syntax}, whose carriers the proofs use as constants and whose operations they use as total and nothing more, and the translation $\llbracket \cdot \rrbracket$ is the one of Section~\ref{app:fjlt:translation}, into System~F with products, sums and the carriers of $\Sigma$ as constants, which is conservative over System~F proper.
A context translates pointwise: $\llbracket \Delta \rrbracket$ has a type variable for each $\alpha \in \Delta$ and a record variable $q_Q : \llbracket Q \rrbracket$ for each assumed constraint $Q \in \Delta$, and $\llbracket \Gamma \rrbracket = \overline{x : \llbracket \tau \rrbracket}$.
Three facts about the target are used without proof: it is strongly normalising~\cite{girard1989proofs} and confluent, and substitution of types for type variables preserves typing.

\begin{lemma}[Dictionaries are well typed]
\label{lem:dict}
If $\Delta \Vdash Q$, then $\llbracket \Delta \rrbracket; \varnothing \vdash \llbracket \Delta \Vdash Q \rrbracket : \llbracket Q \rrbracket$.
\end{lemma}

\begin{proof}
By induction on the entailment derivation, mutually with Theorem~\ref{thm:preservation}, the induction being on the size of the derivation.
\textsc{E-Assume}: the dictionary is the variable $q_Q$, which $\llbracket \Delta \rrbracket$ types at $\llbracket Q \rrbracket$.
\textsc{E-Shape}: $Q = C\texttt{<}\overline{\tau}\texttt{>}$, the dictionary is the record $\{\,\overline{r_i = \llbracket \Delta \Vdash R_i[\overline{\tau}/\overline{\alpha}] \rrbracket}\,\}$, each field has type $\llbracket R_i \rrbracket[\overline{\tau}/\overline{\alpha}]$ by the induction hypothesis, and that is the field type of $\llbracket C\texttt{<}\overline{\tau}\texttt{>} \rrbracket$ by definition.
\textsc{E-Law} and \textsc{E-Law-Assumed}: the dictionary is $\mathit{true} : \mathit{Bool}$.
\textsc{E-Op}: the premise types $e$ at $\tau'$ under $\overline{x : \tau_x}$, so by Theorem~\ref{thm:preservation} on a smaller derivation $\llbracket e \rrbracket : \llbracket \tau' \rrbracket$ under $\overline{x : \llbracket \tau_x \rrbracket}$, and $\lambda\overline{x}.\,\llbracket e \rrbracket : \overline{\llbracket \tau_x \rrbracket} \to \llbracket \tau' \rrbracket$; for \cppinline{std::same_as} $\tau' = \tau$, and for \cppinline{std::convertible_to} the translation inserts the conversion, a constant of type $\llbracket \tau' \rrbracket \to \llbracket \tau \rrbracket$, so the field has type $\overline{\llbracket \tau_x \rrbracket} \to \llbracket \tau \rrbracket$ in both cases.
\end{proof}

\begin{proof}[Proof of Theorem~\ref{thm:preservation}, type preservation]
By induction on the typing derivation, one case per rule.
\textsc{T-Var}: $\llbracket x \rrbracket = x$, and $\llbracket \Gamma \rrbracket$ types it at $\llbracket \tau \rrbracket$.
\textsc{T-Op}, construction: $\llbracket O\texttt{<}\overline{\tau}\texttt{>\{}\overline{e_y}\texttt{\}} \rrbracket = (\overline{\llbracket e_y \rrbracket}, O_{\mathrm{call}}\,\overline{\llbracket e_y \rrbracket})$; the fields have their types by the induction hypothesis, and $O_{\mathrm{call}}\,\overline{\llbracket e_y \rrbracket} : \forall\overline{\beta}.\,\overline{\llbracket Q \rrbracket} \to \overline{\llbracket \tau_x \rrbracket} \to \llbracket \tau \rrbracket$ by the induction hypothesis on the operation's body, typed under $\overline{\beta}, \overline{Q}$ as a generic function's is (for a standard function object, by the assumption on the standard's function), so the pair has type $\llbracket O\texttt{<}\overline{\tau}\texttt{>} \rrbracket$.
\textsc{T-Op}, application: $\pi_2\,\llbracket e \rrbracket$ has the call function's type, is instantiated at the deduced $\overline{\sigma}$, receives the dictionaries $\overline{\llbracket \Delta \Vdash Q[\overline{\sigma}/\overline{\beta}] \rrbracket}$, of the parameter types by Lemma~\ref{lem:dict}, and the arguments, of theirs by the induction hypothesis; projection: $\pi_i\,(\pi_1\,\llbracket e \rrbracket)$ has the field's type.
\textsc{T-Call}: $f$ was declared by \textsc{D-Generic}, so $f = \Lambda\overline{\alpha}.\,\lambda\overline{q : \llbracket Q \rrbracket}.\,\lambda\overline{x}.\,\llbracket e_f \rrbracket$ has type $\forall\overline{\alpha}.\,\overline{\llbracket Q \rrbracket} \to \overline{\llbracket \tau_x \rrbracket} \to \llbracket \tau \rrbracket$ by the induction hypothesis on that declaration; applying it to $\overline{\llbracket \sigma \rrbracket}$ gives, by type substitution, $\overline{\llbracket Q[\overline{\sigma}/\overline{\alpha}] \rrbracket} \to \overline{\llbracket \tau_x[\overline{\sigma}/\overline{\alpha}] \rrbracket} \to \llbracket \tau[\overline{\sigma}/\overline{\alpha}] \rrbracket$; the records have the parameter types by Lemma~\ref{lem:dict}, and the arguments theirs by the induction hypothesis.
\textsc{T-Trait}: the call resolved to a specialisation declared by \textsc{D-Instance}, so $f_{\overline{\sigma}} = \lambda\overline{x}.\,\llbracket e \rrbracket : \overline{\llbracket \tau_x \rrbracket} \to \llbracket \tau \rrbracket$ by the induction hypothesis on that declaration, and the arguments have the right types; if it resolved to a generic function with an entailed context, the case is \textsc{T-Call} with the context's dictionaries.
\textsc{T-Req-Assumed}: $C\texttt{<}\overline{\alpha}\texttt{>} \in \Delta$, so $q_C : \llbracket C\texttt{<}\overline{\alpha}\texttt{>} \rrbracket$ is in $\llbracket \Delta \rrbracket$, the projection $q_C.r$ has the requirement's field type $\overline{\llbracket \tau_a \rrbracket} \to \llbracket \tau \rrbracket$, and the arguments have the parameters' types by the induction hypothesis.
\textsc{T-Fold}, for a range of instance $R$ over $\tau$: $\llbracket r \rrbracket = c_R\,\overline{\llbracket e \rrbracket} : \llbracket R \rrbracket$ by the induction hypothesis on the arguments and the constructor's type, $\mathit{iter}\,[\llbracket R \rrbracket \times \sigma] : \mathbb{N} \to ((\llbracket R \rrbracket \times \sigma) \to \llbracket R \rrbracket \times \sigma) \to \llbracket R \rrbracket \times \sigma \to \llbracket R \rrbracket \times \sigma$, $|\llbracket r \rrbracket| : \mathbb{N}$, and the step has the pair type since $\mathit{next} : \llbracket R \rrbracket \to \llbracket R \rrbracket$, $\mathit{head} : \llbracket R \rrbracket \to \llbracket \tau \rrbracket$ and the callable, elaborated at $\sigma$ and $\tau$ with its type arguments applied and its dictionaries supplied by Lemma~\ref{lem:dict}, has type $\sigma \to \tau \to \sigma$ (curried in the target); $(\llbracket r \rrbracket, \llbracket a \rrbracket)$ has the pair type, and $\pi_2$ of the result has type $\sigma$.
\textsc{T-Cata}: $\mathit{fold}_F\,[\mu F \times \sigma] : (F(\mu F \times \sigma) \to \mu F \times \sigma) \to \mu F \to \mu F \times \sigma$; $\beta$ has the algebra's type since $\mathrm{in}\,(F\,\pi_1\,n') : \mu F$ rebuilds the node, $F\,\pi_2\,n'$ holds the legs' results of type $\sigma$, and $\llbracket \mathit{alg} \rrbracket^{\!\circ}$, elaborated at $\mu F$ and $\sigma$, has type $\mu F \times \sigma^{k} \to \sigma$ by the induction hypothesis; $\llbracket t \rrbracket : \mu F$, and $\pi_2$ of the result has type $\sigma$.
\textsc{D-Generic}: the body is typed under $\overline{\alpha}, \overline{Q}$ and $\overline{x : \tau_x}$, so by the induction hypothesis $\llbracket e \rrbracket : \llbracket \tau \rrbracket$ under type variables $\overline{\alpha}$, record variables $\overline{q : \llbracket Q \rrbracket}$ and $\overline{x : \llbracket \tau_x \rrbracket}$, and the abstraction has the stated polymorphic type; this is the case that uses \textsc{T-Req-Assumed}, since the body reaches an operation on a constrained type only through $\Delta$.
\textsc{D-Instance}: the same with an empty $\Delta$; the declaration order, with instantiations of a self-calling generic function ordered by the size of their type arguments, makes the induction on declarations well founded.
The omitted rules are the textbook cases for pairs, sums and conditionals.
\end{proof}

\begin{lemma}[Dictionaries agree with resolution]
\label{lem:resolve}
If $\Delta \Vdash C\texttt{<}\overline{\sigma}\texttt{>}$ with $\overline{\sigma}$ concrete and $\texttt{\{ }e_r\texttt{ \} -> }S\texttt{<}\tau\texttt{>}$ is a requirement of $C$ with parameters $\overline{a}$, then
\[ \llbracket \Delta \Vdash C\texttt{<}\overline{\sigma}\texttt{>} \rrbracket.r = \lambda\overline{a}.\,\llbracket e_r[\overline{\sigma}/\overline{\alpha}] \rrbracket, \]
in which every call has been resolved; hence for any terms $\overline{e}$,
\[ (\llbracket \Delta \Vdash C\texttt{<}\overline{\sigma}\texttt{>} \rrbracket.r)\,\overline{\llbracket e \rrbracket} \longrightarrow^{+} \llbracket e_r[\overline{\sigma}/\overline{\alpha}][\overline{e}/\overline{a}] \rrbracket, \]
in two steps, a projection and a $\beta$-reduction.
\end{lemma}

\begin{proof}
The field is built by \textsc{E-Op} as $\lambda\overline{a}.\,\llbracket e_r[\overline{\sigma}/\overline{\alpha}] \rrbracket$, where the instantiated expression is typed at concrete types, so its calls are \textsc{T-Trait} or \textsc{T-Call} and translate to resolved terms; a projection of the constructed record followed by $\beta$-reduction on $\overline{\llbracket e \rrbracket}$, which full $\beta$-reduction permits whether or not the arguments are values, gives the stated term, the translation commuting with substitution.
\end{proof}

\begin{lemma}[Progress]
\label{lem:progress}
A closed well-typed term is a value or takes a step.
\end{lemma}

\begin{proof}
By induction on the typing derivation.
If some proper subterm in an evaluation position is not a value, the leftmost such subterm steps by the induction hypothesis, and \textsc{S-Ctx} lifts the step.
Otherwise the term is a value, or a redex of one of the following shapes, each of which steps.
A call $f\texttt{<}\overline{\sigma}\texttt{>(}\overline{v}\texttt{)}$ typed by \textsc{T-Call} or \textsc{T-Trait}: the premise says the call resolves (for \textsc{T-Call}, the constraints are entailed, so resolution finds the generic function or, through its context, a specialisation), and the body it resolves to precedes the call by the declaration order, so \textsc{S-Call} applies; \textsc{T-Req-Assumed} cannot occur in a closed term, since $\Delta$ is empty.
An application $O\texttt{<}\overline{\tau}\texttt{>\{}\overline{v_y}\texttt{\}(}\overline{v}\texttt{)}$: \textsc{S-Op} for a declared operation, \textsc{S-Std} for a standard one, whose operations are total by the choice of $O$.
A primitive $c_1 \oplus c_2$: \textsc{S-Prim}, total by the choice of $\oplus$.
A conditional on a constant of type \cppinline{bool}, a case on a value of a sum, which by \textsc{T-Case} and canonical forms is an injection, a projection of a pair or of a constructed object, an unbox of a box, a fold whose count is a constant, and a \cppinline{cata} on a node: \textsc{S-If}, \textsc{S-Case}, \textsc{S-Proj}, \textsc{S-Unbox}, \textsc{S-Fold}, \textsc{S-Cata}, with \textsc{S-Fold}'s two cases covering every constant and \textsc{S-Cata} covering every node, leaves included.
Preservation along a step, that $e \longrightarrow e'$ keeps the type, is the usual substitution argument and is used below without further comment.
\end{proof}

\begin{lemma}[Forward simulation]
\label{lem:forward}
If $e \longrightarrow e'$ then $\llbracket e \rrbracket \longrightarrow^{+} \llbracket e' \rrbracket$, and every value translates to a value.
\end{lemma}

\begin{proof}
Values: constants to constants, function objects to pairs of values, pairs to pairs, optionals to injections, boxes to pairs with unit.
Steps, by cases on the rule; by \textsc{S-Ctx} and the fact that the translation of a context is a context, it suffices to treat the redex.
\textsc{S-Call} to a specialisation: $f_{\overline{\sigma}}\,\overline{\llbracket v \rrbracket}$ $\beta$-reduces to $\llbracket e_f \rrbracket[\overline{\llbracket v \rrbracket}/\overline{x}] = \llbracket e_f[\overline{v}/\overline{x}] \rrbracket$.
\textsc{S-Call} to a generic function: $f\,\overline{\llbracket \sigma \rrbracket}\,\overline{d}\,\overline{\llbracket v \rrbracket}$ reduces by type application and $\beta$-reduction to $\llbracket e_f \rrbracket$ with $\overline{\llbracket \sigma \rrbracket}$ for $\overline{\alpha}$, $\overline{d}$ for $\overline{q}$ and $\overline{\llbracket v \rrbracket}$ for $\overline{x}$; in it, each use of a requirement, translated as $q.r\,\overline{\llbracket e \rrbracket}$, has become $d.r\,\overline{\llbracket e \rrbracket}$ with $d$ a record constructed by \textsc{E-Shape}, the term being closed, and by Lemma~\ref{lem:resolve} each reduces in two steps to the translation of the resolved instance applied to the same arguments; the result is $\llbracket e_f[\overline{\sigma}/\overline{\alpha}][\overline{v}/\overline{x}] \rrbracket$, the term the source stepped to, whose requirement uses are typed by \textsc{T-Trait} at the concrete types.
\textsc{S-Op}: $(\pi_2\,(\overline{\llbracket v_y \rrbracket}, O_{\mathrm{call}}\,\overline{\llbracket v_y \rrbracket}))\,[\overline{\sigma}]\,\overline{d}\,\overline{\llbracket v \rrbracket}$ reduces by projection, type application and $\beta$-reduction to $\llbracket e_O \rrbracket$ with fields, dictionaries and arguments substituted, which is $\llbracket e' \rrbracket$ by the same argument as for a generic call.
\textsc{S-Std} and \textsc{S-Prim}: one $\delta$-step to the constant the standard assigns, by the assumption that the primitives' translations compute the standard's functions on constants.
\textsc{S-If}, \textsc{S-Case}, \textsc{S-Proj} and \textsc{S-Unbox}: a case reduction, a case reduction to the translation of the selected application, whose evaluation is the next step's, a projection, a projection; the box is a unary product rather than nothing so that unboxing is a step on both sides and the simulation stays strict.
\textsc{S-Fold} with $|r| = k + 1$:
\[ \mathit{iter}\,(k{+}1)\,\mathit{step}\,(\llbracket r \rrbracket, \llbracket a \rrbracket) \longrightarrow \mathit{iter}\,k\,\mathit{step}\,(\mathit{step}\,(\llbracket r \rrbracket, \llbracket a \rrbracket)) \longrightarrow^{+} \mathit{iter}\,k\,\mathit{step}\,(\llbracket \mathit{next}\,r \rrbracket, \llbracket f \rrbracket^{\!\circ}\,\llbracket a \rrbracket\,\llbracket \mathit{head}\,r \rrbracket), \]
the constants $\mathit{next}$ and $\mathit{head}$ computing the range's operations, and the last term is $\llbracket \texttt{fold\_left(}\mathit{next}\,r\texttt{, }f\texttt{(}a\texttt{, }\mathit{head}\,r\texttt{), }f\texttt{)} \rrbracket$ since $|\mathit{next}\,r| = k$; the empty case is one step of the iterator followed by a projection.
\textsc{S-Cata}: $\mathit{fold}_F\,\beta\,(\mathrm{in}\,n) \longrightarrow \beta\,(F(\mathit{fold}_F\,\beta)\,n)$ is one step of the term's iterator; $\beta$ then rebuilds the node from the first components, which reduces to $\llbracket n \rrbracket$ since each leg's pair has that leg as its first component, and applies $\llbracket \mathit{alg} \rrbracket^{\!\circ}$ to it and to the second components $\pi_2\,(\mathit{fold}_F\,\beta\,\llbracket l_i \rrbracket)$, which are $\llbracket \texttt{cata(}\mathit{alg}\texttt{, }l_i\texttt{)} \rrbracket$; after those projections the term is the translation of the source's reduct.
\end{proof}

\begin{proof}[Proof of Corollary~\ref{cor:termination}, termination]
An infinite reduction $e \longrightarrow e_1 \longrightarrow \cdots$ would give, by Lemma~\ref{lem:forward}, an infinite reduction $\llbracket e \rrbracket \longrightarrow^{+} \llbracket e_1 \rrbracket \longrightarrow^{+} \cdots$ in the target, which is strongly normalising~\cite{girard1989proofs}.
The count enters as a natural number iterated by a primitive of the target, not as a recursion scheme the type system would have to admit.
\end{proof}

\begin{proof}[Proof of Corollary~\ref{cor:soundness}, type soundness]
Let $e$ be closed and well-typed at a base type.
By Lemma~\ref{lem:progress} and preservation along steps, every term in the reduction sequence from $e$ is closed and well-typed, so each is a value or steps; by Corollary~\ref{cor:termination} the sequence is finite; so it ends in a value $v$, and at a base type a value is a constant.
\end{proof}

\begin{proof}[Proof of Theorem~\ref{thm:simulation}, simulation]
The first two claims are Lemma~\ref{lem:forward}.
For the converse at a base type: if $e \Downarrow v$ then $\llbracket e \rrbracket \longrightarrow^{*} \llbracket v \rrbracket$ by Lemma~\ref{lem:forward} and induction on the sequence.
Conversely, if $\llbracket e \rrbracket \longrightarrow^{*} c$ for a constant $c$: by Corollary~\ref{cor:soundness} $e \Downarrow v$ for some $v$, so $\llbracket e \rrbracket \longrightarrow^{*} \llbracket v \rrbracket$ by the half just proved, and $c = \llbracket v \rrbracket$ since the target is confluent and both are normal forms.
\end{proof}

\begin{proof}[Proof of Theorem~\ref{thm:coherence}, coherence]
Resolution is a function by well-formedness: at concrete types one specialisation at a head and a unique most specific generic function among the entailed candidates, and at a type variable only a call its context decides, so that the declaration a body's call resolves to is the same at every instantiation of the body and the dictionary built at the type variable is the one built after substitution; contexts are well-founded, so the recursion through contexts terminates with one answer.
\textsc{E-Not} applies only at concrete types, where entailment is decided, and only to a negation not already assumed, as \textsc{E-Shape} applies only to a shape not in $\Delta$, so it adds no choice.
The entailment rules are syntax-directed, exactly one rule per constraint: \textsc{E-Assume} for a constraint in $\Delta$, \textsc{E-Shape} for a shape not in $\Delta$, by its side condition, \textsc{E-Op} for an operation, and \textsc{E-Law} or \textsc{E-Law-Assumed} for a law, which build the same $\mathit{true}$; so two derivations of $\Delta \Vdash Q$ have the same shape, and by induction on that shape they build the same dictionary: the same variable, the same record of fields by the induction hypothesis, the same $\mathit{true}$, the same $\lambda\overline{x}.\,\llbracket e \rrbracket$ in which every trait call resolved the same way.
\textsc{T-Req-Assumed} and \textsc{E-Law-Assumed} are deterministic as well, taking the leftmost assumed shape and its first matching requirement in declaration order, nested shapes included, so the translation of a body is a function of the body.
\textsc{T-Call} names the declaration resolution selects, so a call has one derivation even where several generic functions of one name have entailed contexts.
Hence $\llbracket \Delta \Vdash Q \rrbracket$ depends only on $\Delta$ and $Q$, the records in \textsc{T-Call} are determined by the program, and the translation is a function of it.
\end{proof}

\begin{proof}[Proof of Corollary~\ref{cor:parametricity}, parametricity]
By Theorem~\ref{thm:preservation}, a generic FJlt function translates to a closed System~F term of type $\forall\overline{\alpha}.\,\overline{\llbracket Q \rrbracket} \to \overline{\llbracket \tau_x \rrbracket} \to \llbracket \tau \rrbracket$; Reynolds' abstraction theorem~\cite{reynolds1983types} gives its free theorem, in which the record parameters are ordinary term parameters, so the theorem relates behaviour at two instantiations through the relation between their records.
\end{proof}

The dependencies run one way: preservation and the two lemmas on dictionaries; progress; forward simulation; termination from forward simulation and the target's strong normalisation; soundness from progress and termination; the converse of simulation from soundness; coherence and parametricity on their own.
What the proofs do not do: they induct over the rules of Figures~\ref{fig:fjlt-typing} and~\ref{fig:fjlt-eval} as given, which omit the generic cases, and they take \cppinline{fold_left} over the ranges of $\mathcal{R}$ as a primitive with the evaluation rule of Figure~\ref{fig:fjlt-eval}, trusting the standard library for \cppinline{repeat} and \cppinline{iota} and the library for \cppinline{chain_view}, as Section~\ref{sec:translation:adequacy} says.
Their mechanisation is future work.

\subsection{The compiler's own functional language}
\label{app:fjlt:ssa}

Section~\ref{sec:binding} said that instantiation is partial evaluation of the translated term at a static type.
What that evaluation leaves is a closed first-order term over the base types: the type abstractions are gone with their arguments, the record parameters are gone with the records the compiler resolved, every trait call is a call to one specialisation, and the only recursion left is $\mathit{iter}$ and $\mathit{fold}_F$.
The compiler then lowers that term to its intermediate representation, and the representation is in static single assignment form~\cite{cytron1991ssa}: every variable is assigned exactly once, and where two paths of control join, a $\phi$-node names the value that arrives along each.

SSA is a functional language.
Kelsey showed it to correspond to continuation-passing style~\cite{kelsey1995correspondence}, and Appel put the correspondence as a slogan~\cite{appel1998ssa}: a basic block is a local function, its $\phi$-nodes are that function's parameters, a branch is a tail call that passes the arguments, and dominance is lexical scope.
So a Jlt function is translated twice into a functional language, by this appendix into System~F with records and iterators, and by the compiler into first-order functions with tail calls, with instantiation between the two; Rules~1 and~3 are what makes the source already look like the second.

template <typename P>
concept IsPredicate = std::semiregular<P> && requires(const P p, size_t n) {
  { p(n) } -> std::same_as<bool>;
};

template <IsPredicate P>
constexpr std::pair<size_t, bool> advance(std::pair<size_t, bool> s, size_t i) {
  return s.second ? s : std::pair{i, P{}(i)};
}

constexpr std::optional<size_t> found(std::pair<size_t, bool> s) {
  return s.second ? std::optional{s.first} : std::nullopt;
}

template <IsPredicate P>
constexpr std::optional<size_t> first(size_t budget) {
  return found(std::ranges::fold_left(std::views::iota(size_t{0}, budget),
                                      std::pair{size_t{0}, false}, advance<P>));
}

struct Over1000 {
  constexpr bool operator()(size_t n) const { return n * n > 1000; }
};

static_assert(first<Over1000>(40) == 32);
static_assert(!first<Over1000>(30));

\end{cpp}

Listing~\ref{lst:ssa} is the search of Listing~\ref{lst:fuel}, \cppinline{first<Over1000>} behind a non-template wrapper, as the compiler leaves it before it unrolls the loop.
The fold over \cppinline{iota(0, budget)} with \cppinline{advance} is one loop, and its header has three $\phi$-nodes: the two components of the state, the candidate and whether it has been found, and the position in the range.
Those are the iterator's state in Figure~\ref{fig:fjlt-translation}, the pair $(\llbracket r \rrbracket, \llbracket a \rrbracket)$ with $\llbracket a \rrbracket$ itself a pair, and the count $|r|$, here $\llbracket j \rrbracket - \llbracket i \rrbracket$, is the comparison that ends the loop.
The exit block's two $\phi$-nodes are the fold's result, which \cppinline{found} reads out into the optional.
Nothing else survives: not \cppinline{IsPredicate}, not the record its constraint became, not the range object, not the pair; the predicate is the multiplication and the comparison in the loop body, and the budget is the register the wrapper was called with.

What this adds to the adequacy argument is a reason, not a theorem.
Theorem~\ref{thm:simulation} relates FJlt's evaluation to the System~F image; the compiler relates the same program to SSA; and since both targets are functional languages with the loop's state as an explicit parameter, the sentence of Section~\ref{sec:binding}, that the discipline costs nothing at runtime, has a structural ground: the compiler makes a local function of every loop and a parameter of every accumulator in any case, and a Jlt fold names that parameter in the source instead of leaving the compiler to recover it from assignments.
It is not a theorem because the compiler is not one of the hypotheses: the lowering is trusted, as every \Cpp{} program trusts it, and the reading of SSA as the simply typed iterator terms is Appel's, which this paper uses and does not prove.
One seam shows here too: SSA's values are the scalars in registers, and a value that lives in memory, a boxed value in particular, is read and written through a pointer that no $\phi$-node carries, which is the same line between a value and a cell that Rule~1 draws.
The same line is an optimisation when it falls on the right side.
Of the types of Figure~\ref{fig:fjlt-syntax}, the box and \cppinline{std::string} allocate; a value of any other type lives in a register or on the stack, and the top of the stack is the part of memory that is in cache almost always, so a function of such values has next to no cache to miss, and the two exhibits, both over scalars, have no load and no store at all.
That is an observation about the exhibits and a tendency with a reason for the rest, not a guarantee: a boxed value is on the heap by definition, a string's characters too, a large value is passed through the stack, and the register allocator, not the rule, has the last word; what the rule does is remove every reason to keep state anywhere but in the frame of the function that owns it, which is the identification of \cppinline{const T} with \cppinline{const T&} of Section~\ref{sec:posture} read by the machine.

\subsection{The sugar: closure under the host's constructions}
\label{app:fjlt:closure}
FJlt is the kernel of Jlt, and this section names the sugar: each construction of \Cpp{} that a Jlt program writes beyond the kernel's grammar, with its desugaring into the kernel and without a proof.
Most of the desugarings are local in Felleisen's sense~\cite{felleisen1991expressive}; two are not, closure conversion and the split of a branch on a constraint into two functions, since both add declarations, which is one reason the sugar is named and its desugaring trusted rather than proved.
The question is one of closure: given terms of FJlt, under which condition is their composition under a construction of \Cpp{} again a term of FJlt?
That is the question Section~\ref{sec:translation:adequacy} leaves open for the constructions the grammar does not name, and this section answers it one construction at a time.
Each answer is a closure statement: the construction, the condition, and the FJlt term it builds.
The condition is always on how the term is built and never on inspecting it afterwards, which is what lets a closure, an object whose type has no name, be a term of the calculus.
Tables~\ref{tab:closure} and~\ref{tab:closure:decl} are the summary, with a column for what the calculus lacks today to state each lemma, since that column is what decides the scope of the calculus.
The statements come with the reason each holds, and none of them is used by the theorems of Appendix~\ref{app:fjlt:theorems}.
Where a count is given it is measured on the library's \texttt{category} module, 35 files.

\paragraph{Lambdas.}
A lambda \cppinline{[c...](const τ x...) { return e; }} whose captures are FJlt values taken by copy and whose body is an FJlt term under those captures and parameters is the operation struct with the captures as fields and \cppinline{e} as the body of its call operator.
A generic lambda written with a template head and a \cppinline{requires} clause is the operation with a generic call operator.
The reason is the standard's own definition of the closure type: a class with the copied captures as members and a \cppinline{const} call operator, which is the operation production of Figure~\ref{fig:fjlt-syntax} to the letter.
Capture by reference is excluded by Rule~1 before this lemma is reached.
A capturing closure type is copy constructible and neither default constructible nor assignable, so it is not \cppinline{std::semiregular} and Rule~1 does not admit it as a value; it is admitted as sugar, judged through its image, which is semiregular when its captures are.
That is the general rule for sugar: the rules are asked of the kernel term.
A closure type has no name, so a lambda is never a carrier and never the head of an instance, and nothing in the lemma asks to look inside it once built.
The library has 47.

\paragraph{\texttt{if constexpr} on a value.}
A body \cppinline{if constexpr (p) return A; else return B;} with \cppinline{p} a closed \cppinline{bool} term, a law or a trait read, and \cppinline{A}, \cppinline{B} FJlt terms of one type under the same context, is the term \cppinline{p ? A : B}.
The condition is stronger than \Cpp{} asks, since \Cpp{} does not instantiate the discarded branch and FJlt types both, and the compiler decides it: the rewritten body compiles or it does not.
Constant evaluation of the two spellings agrees because both evaluate \cppinline{p} first and then one branch.
36 of the library's 81 \cppinline{if constexpr} test a value, a syntactic count; whether the two branches share a type is decided per site by the rewrite, and a site whose branches differ in type, \cppinline{lattice_term}'s \cppinline{Meet<RA, RB>} against \cppinline{Meet<RB, RA>}, is not this row but a branch on types in a value's clothing, and waits with the next.

\paragraph{\texttt{if constexpr} on a constraint.}
A body \cppinline{if constexpr (C<T>) return A; else return B;} in a generic function with head $\overline{Q}$, where \cppinline{A} is an FJlt term under $\overline{Q}, C\texttt{<T>}$ and \cppinline{B} one under $\overline{Q}, \texttt{!}C\texttt{<T>}$, is the pair of generic functions with those two heads.
The pair is an instance chain in the sense of Morris and Jones~\cite{morris2010instance}, an explicit alternation decided by one constraint, and resolution by specificity (Appendix~\ref{app:fjlt:typing}) picks its branch: at a concrete type the compiler decides $C\texttt{<T>}$, and at a type variable the call resolves only where the enclosing context decides it.
A call it cannot decide is the next row's.
When the test is \cppinline{std::same_as<T, X>} at a concrete \cppinline{X} and \cppinline{T} is the whole head, the first function is an explicit specialisation at \cppinline{X}.
45 of the library's 81 \cppinline{if constexpr} test a constraint; 7 of those tested a \cppinline{requires} expression written in the body, which Rule~2 does not count as a declared constraint, and are now named shapes, with the tool's \texttt{inline-requires} check holding the module at zero.

\paragraph{A call its clause does not decide.}
A generic function whose body calls a chain at its own type variable, without a clause that entails the chain's constraint or its negation, varies with the type through a constraint it did not declare.
\Cpp{} accepts it and resolves the call at each instantiation; the kernel refuses it, by GHC's rule.
Its desugaring is constraint inference: the call's resolution becomes a parameter of the enclosing function, which each caller supplies after resolving it at a concrete type, where resolution is a function, so the kernel term agrees with what \Cpp{} instantiates.
The price is in the free theorem, which now ranges over that parameter.
Written by hand, the same thing is to decide the constraint in the clause, by requiring it or by splitting on it.

\paragraph{Sums.}
The kernel has the case form (Appendix~\ref{app:fjlt:syntax}), so given FJlt terms \cppinline{f} and \cppinline{g} on the two summands their copairing is an FJlt term, \texttt{case(}$s$\texttt{, }$f$\texttt{, }$g$\texttt{)}.
\cppinline{has_value} and \cppinline{value_or} on an optional are that case on $1 + T$, and \cppinline{std::visit(O{}, v)} is the case whose branches are one generic call operator entailed at each summand.
\cppinline{*} on an optional is partial, undefined on the empty one, and is admitted only under a \cppinline{has_value} guard, which desugars to the case form, as the head of a range is admitted only when its length is positive.
The library's \cppinline{IsCoproduct} writes down the injection half of the condition on $\mathcal{S}$, two named injections into one type, with \cppinline{std::variant} as its instance; the case form and its equations, \texttt{case} after an injection is that branch, are the other half, which no concept checks and which $\mathcal{S}$ states as $\mathcal{R}$ states head and tail.

\paragraph{Variable and class templates.}
A variable template \cppinline{v<T...> = e} is the nullary function template \cppinline{v<T...>() { return e; }}, and a class template with a static constant member is the same, since constant evaluation of the three agrees.
A partial specialisation over a family, every \cppinline{Rational<I>} under \cppinline{+}, is an instance with a context, in the grammar.
Nothing is missing for one family; a primary that answers \cppinline{false} beside families that answer \cppinline{true} is two generic functions whose heads both match, which resolution by specificity orders.
The host adds a wall the calculus does not have: a constrained function overload is found only when it precedes the shape (Section~\ref{sec:limits}), so the FJlt spelling is not writable in the library's module layout, while the library's spelling is FJlt by this lemma.
The library has 225 registrations.

\paragraph{Member functions.}
A \cppinline{const} member function \cppinline{τ m(τ x...) const { return e; }} of an operation is the generic function \cppinline{m(O self, τ x...)} whose body reads the fields of \cppinline{self} where the member read \cppinline{this}.
A static member function is a generic function.
A struct with fields and no call operator is a product, nested pairs.
Rule~1 supplies the \cppinline{const}, and the body is FJlt by hypothesis, so nothing is missing.
The library has 12.

\paragraph{Abbreviations.}
An alias template is substitution.
\cppinline{std::tuple} of FJlt types is nested pairs.
\cppinline{std::array<T, n>} is a product of $n$ copies and also a member of $\mathcal{R}$, with length $n$, a head and a tail, so a fold over it is already in the grammar.

\paragraph{Overloading.}
Overloads of one name at distinct concrete carriers are explicit specialisations of one trait.
Constrained overloads are generic functions, and where their heads both match, resolution by specificity orders them, as for Listing~\ref{lst:desugar}'s \cppinline{times}.

\paragraph{Inheritance.}
Jlt has no subtyping: the grammar has no base clause and no derived-to-base conversion, a class with a base that holds state or a virtual function is outside the posture, and the tool's \texttt{inheritance} check holds the module at zero.
What the library writes with a base clause is a registration, \cppinline{struct is_involutive<X> : std::true_type}, 44 of them in the module and every base an empty class: the family row spelled by inheritance, read as the fact it states.
The one class that inherited state, a wrapper around \cppinline{Morphism}, had no users and is gone.

\paragraph{What the table says.}
Every row needs nothing from the calculus, the closure lemma being the standard's own account of the construction, once resolution is by specificity under GHC's rule and sums have their case form.
The table is complete by measurement, not by argument, at the resolution of a syntax node's kind: the repository's tool lists every kind the \texttt{category} module and the listings write, leaving out the compiler's implicit wrappers, and each is the kernel's or a row of the table.
A kind does not tell every use apart: a binary operator is arithmetic or an assignment, and the assignments are the row of local state, which Rule~1's footnote admits and which reading, not counting, finds.
One construction the measurement found had no image in System~F, a template taking a class template as an argument, a type constructor of higher kind; the library used it once, for convenience, and no longer does.
With the table closed, the second direction of Section~\ref{sec:translation:adequacy} reads: a Jlt program built from the grammar by these constructions under their conditions is an FJlt program.
