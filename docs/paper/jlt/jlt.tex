\begin{abstract}
Parametric polymorphism, type classes and structural recursion let a functional programmer state what a program does and have a type checker enforce the statement.
\Cpp{23}, which runs much of machine learning and most embedded devices, has the material for them: compile-time evaluation of ordinary functions and of most of the standard library, concepts, and folds over ranges.
It does not hold a generic function to its declared constraints: the body may use any operation its type argument happens to have.

\Cpp{} is a mainstream language with zero-overhead abstraction but few guarantees about generic code; System~F offers those guarantees, and Haskell's type classes are the established way for overloading to reach it.

We restrict \Cpp{23} to what can be evaluated at compile time under three rules: values are copyable data and functions are pure; generic code varies with a type only through that type's concepts and traits; and recursion is bounded before its first step.
This drops input and output, state that outlives a call, and unbounded data and computation.
What remains, the Juliet Posture or Jlt, is ordinary \Cpp{23} with templates, concepts and overloading, and needs no extension and no tool to compile.

Jlt is a part of the \Cpp{} that can be evaluated at compile time in which every definition also has a meaning in System~F.
Its kernel, Featherweight Jlt (FJlt), translates into System~F by dictionary passing, and the rest of Jlt is sugar, such as local state and loops, that desugars into the kernel.
The translation is defined on every well-typed kernel program and proved on paper to preserve types and values.
The desugaring is argued and tested, not proved.
That \Cpp{} evaluates a kernel program as the calculus does is assumed, with constant evaluation, which every compiler performs, as the reference it is tested against.

Laws are stated as plain \Cpp{} traits, and a declared law licenses a faster program through specialisation and constant folding.
We present a linter with an extensible rule book.
It scans a \Cpp{} code base and classifies each definition, with its reason, as shown to be in Jlt, not shown to be, or undecided, and it lists the laws the code takes on trust.
We apply it to the library whose development motivated Jlt and to Catch2, a well-known third-party library.

\Cpp{23} already contains a language that reads as System~F, and staying inside it takes a linter, not a new compiler.
\end{abstract}
